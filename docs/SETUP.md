# WaveTagger Rec の設定 (最初の 1 回だけ)

スマホのブラウザで録音すると、48 kHz / 24 bit の WAV が自動で Google Drive の指定フォルダに保存されます。
パソコンの WaveTagger の Inbox がそのフォルダを監視しているので、あとは自動で取り込まれます。

## 1. Google Cloud で OAuth クライアント ID を作る (無料・約 10 分)

1. <https://console.cloud.google.com/> を開き、プロジェクトを新規作成 (名前は何でもよい。例: WaveTagger)。
2. 「API とサービス」→「ライブラリ」→ **Google Drive API** を有効にする。
3. 「API とサービス」→「OAuth 同意画面」
   - ユーザーの種類: **外部**
   - アプリ名: WaveTagger Rec、サポートメール・連絡先: 自分のアドレス
   - スコープは追加しなくてよい (次のステップで画面から使う権限として扱われる)
   - **テストユーザー** に自分の Google アカウントを追加 (公開はしない)
4. 「API とサービス」→「認証情報」→「認証情報を作成」→ **OAuth クライアント ID**
   - アプリの種類: **ウェブ アプリケーション**
   - 承認済みの JavaScript 生成元: `https://nobuokiyota.github.io`
   - 作成後に出る **クライアント ID** (`xxxx.apps.googleusercontent.com`) をコピー (クライアントシークレットは不要)

テストユーザーのまま使うと、ログイン時に「このアプリは Google で確認されていません」と出ます。
「詳細」→「WaveTagger Rec (安全でないページ) に移動」で進めます (自分で作ったアプリなので問題ありません)。

## 2. 公開 (GitHub Pages)

リポジトリの Settings → Pages → Branch を `main`、フォルダを `/docs` にして保存。
数分後に <https://nobuokiyota.github.io/WaveTagger/> で開けます。

## 3. スマホで

1. Android の Chrome で上の URL を開き、メニューから「ホーム画面に追加 / アプリをインストール」。
2. 上の「設定」タブの「Google Drive」に次の 2 つを入れて「保存」。
   - OAuth クライアント ID: 手順 1 でコピーしたもの
   - 保存先フォルダ: Drive で、パソコンの Inbox が見ているフォルダ (例: `PCM録音/_Inbox`) を開き、その URL を貼る
3. 「Google に接続」を押してログインし、権限を許可する。
4. 録音の前に、「入力レベルを確認」を押すと、録音せずにマイクのレベルが見えます (ピーク、LUFS)。声を出したり、音を鳴らして、メーターが 0 dB に届かない程度 (目安は -12〜-6 dB) になるよう、マイクとの距離を調整します。メーターをタップすると、ピーク・CLIP・Integrated がリセットされます。
5. 「録音」を押すと開始、「停止」で保存します。接続が有効 (約 1 時間) なら、そのまま Drive へ送信します。**接続が切れていても、ログインの画面には飛びません**。録音は端末に「送信待ち」で残り、画面に「Google に接続して送信」の帯が出ます。都合のよいときにそれを押すと、まとめて送信します。
6. 録音が無音 (マイクの音が届いていない) のときは、保存も送信もせず、その旨を表示します。

### 画面の構成 (タブ)

画面は 3 つのタブに分かれています。**録音**のタブには、録音中に要るものだけが載り、スクロールしません (縦画面でも横画面でも 1 画面に収まります)。
- **録音**: レベルメーター、ラウドネス、ステレオスコープ、相関、時間、「入力レベルを確認」と録音ボタン
- **履歴**: 最近の録音と、Drive への送信状態 (未送信のアップロード)
- **設定**: 録音フォーマット、入力の診断 (マイクが何チャンネル届けているか)、Google Drive の設定

設定が空のときは、最初に「設定」タブが開きます。

**設定入りのリンク**: アドレスの後ろに `#cid=<クライアント ID>&f=<フォルダの URL か ID>` を付けて開くと、設定欄が自動で埋まります (アドレスからはすぐ消えます)。このリンクを QR コードにしておけば、ブラウザを変えたときや機種変更のときも、入力しなくて済みます。

### 録音フォーマット

画面の「録音フォーマット」で、**ステレオ / モノラル**、**48 / 44.1 kHz**、**24 / 16 bit** を切り替えられます (初期値は ステレオ・48 kHz・24 bit。端末に覚えさせます)。録音中は変えられません。レベル確認中に変えると、新しい設定でマイクを開き直します。
- ステレオを選んだとき、アプリはまず「ちょうど 2 チャンネル」を要求し、断られたら「できれば 2」で取り直します。**実際に届いた音のチャンネル数**で、ステレオかモノラルかを決めます (ブラウザの報告は当てにしません)。1 チャンネルしか届かなければ、モノラルで録音されます (画面に表示されます)。
- 画面の小さな行に、判定の根拠が出ます (「入力: マイクの名前 · ブラウザの報告: ○ ch · 届いた音: ○ ch」)。2 チャンネル届いても、左右がまったく同じ音のとき (内蔵マイクがモノラルのとき) は、「左右がまったく同じ音です」と出ます。Chrome は端末の内蔵マイクをモノラルで渡すことがあります。外付けのステレオマイクや USB オーディオインターフェースなら、2 チャンネルになります。
- モノラルを選んで、2 チャンネルのマイク (外付けなど) をつないでいるときは、2 つを混ぜて 1 チャンネルにします。
- 16 bit はファイルが小さくなります (ディザつき)。素材として使うなら、24 bit のままがおすすめです。

### 画面の向き

スマホは傾けると画面の向きが勝手に変わります。**初期値は「横」** で、開いて最初にタップしたときに横に固定します (固定できない端末では何も言わず、そのままにします)。右上の「向き」ボタンで、**自動 → 横 → 縦 → 自動** と切り替えられ、自分で選んだ向きは覚えていて、次に開いたときの最初のタップで固定し直します。
- Android の Chrome では、向きの固定に全画面が必要なことがあり、そのときは自動で全画面になります。戻る操作で全画面を抜けると、「自動」に戻ります。
- iPhone では、ブラウザから向きを固定できません (「この端末では向きを固定できません」と出ます)。本体の画面の回転ロックを使ってください。
- 横向きでは、**L のメーターを画面の左端、R のメーターを右端**に、縦長に出します (目盛りは内側)。真ん中に、ラウドネスの数字、時間、ボタンが並びます。

### ステレオスコープ (ステレオのときだけ)

録音タブの四角い表示は、左右の音の関係を見るものです。**タップすると、Polar Sample と Lissajous が切り替わります** (選んだほうを覚えます)。
- **Polar Sample**: 半円。真上 (M) が左右同じ音 (モノラル成分)、左上の線 (L) は左だけ、右上の線 (R) は右だけの音、横に寄るほど左右が逆位相です。点の距離は音量 (dB。外側が 0 dBFS、-18、-36 の目盛り)。小さい音も中央の点にならずに見えます。点が真上の細い帯なら、ほぼモノラルの音です。
- **Lissajous**: 古典的なゴニオメーター。縦が左右の和、横が差。小さい音は自動で拡大します (右上の「+○ dB」が拡大量)。縦に細い線ならモノラル、広がるほどステレオ感があります。
- **相関** (下の帯): 約 0.5 秒の左右の相関。**+1 は左右がまったく同じ音 (モノラル)**、0 付近は広がりのある音、**マイナスは逆位相** (モノラルにすると音が消える・やせる)。目安として、+0.3〜+0.9 が自然なステレオです。

### レベル表示の見かた

- メーター: 入力のピーク。ステレオのときは **L と R の 2 本** (左右の偏りが見えます。L と R がまったく同じ動きなら、中身は同じ音のコピーです)、モノラルのときは 1 本 (M)。白い線はピークホールド。CLIP はサンプルが 0 dBFS に当たった印で、タップするまで残ります。
- Momentary: 直近 0.4 秒のラウドネス。Short-term: 直近 3 秒 (3 秒たつまでは、あるだけの長さ)。Integrated: 録音を始めてからの全体 (無音は除く)。単位は LUFS (ITU-R BS.1770 / EBU R128)。

## Android アプリ版 (`android/WaveTaggerRec`、本物のステレオで録る)

ブラウザ版は端末によって左右が同じ音 (モノラルの複製) になるので、Android ではアプリ版を使います。画面はこのページと同じです。

1. **APK を入れる**: ビルドした `app-debug.apk` を Drive (`pcm録音/WTRec.apk`) に置き、スマホの Drive アプリから開いてインストールします (上書きで入れ直せます)。
2. **OAuth クライアント (最初の 1 回)**: Cloud Console で種類 **Android** のクライアントを作ります。パッケージ名 `jp.wavetagger.rec`、SHA-1 は APK の署名鍵のもの (`apksigner verify --print-certs <apk>` で確認。このPCのデバッグ鍵は `F4:9D:90:D2:DB:51:82:0E:7B:57:B7:97:98:B9:88:99:7C:A3:D9:61`)。ブラウザ版のクライアント ID とは別物で、アプリには入力しません。Drive API を有効にし、同意画面がテスト状態なら自分をテストユーザーに入れます (テストのままだと同意は約 7 日で切れます)。
   - **複数の PC でビルドする時**: デバッグ鍵は PC ごとに違うので、そのままでは別の PC でビルドした APK をスマホに上書きできず、Google の接続も通りません。最初に登録した PC の `%USERPROFILE%\.android\debug.keystore` を Drive に置き、各 PC の `android/WaveTaggerRec/local.properties` に `signingStore=<そのパス>` と書くと、どの PC でも同じ鍵で署名されます。
3. **保存先フォルダ**: ビルド時に `android/WaveTaggerRec/local.properties` の `defaultFolder=<Inbox のフォルダ ID>` を入れておくと、再インストール後も最初から入っています。画面の設定タブで変えることもできます。
4. 設定タブの「Google に接続」で同意すると、以後は録音を止めた時に自動で送られます (画面オフ・アプリを閉じていても送信待ちは続きます)。エラーは設定タブの接続表示に出ます (`status=8` = 登録の署名・パッケージが合っていない、`status=10` = クライアントの設定違い)。
5. 初回に設定タブの「左右の自動調整」で、端末の左右の向きを合わせます。

## 注意

- 録音中は画面を点けたままにしてください (画面を消す・別アプリに切り替えると、ブラウザがマイクを止めることがあります)。
- 接続は約 1 時間で切れます。切れると「Google に接続して送信」の帯が出ます (録音の途中や停止のときにウィンドウは出ません)。ブラウザだけのアプリでは、Google のログインを完全に裏で行うことはできません (利用者の操作で開く決まりです)。オフラインで録った分は「送信待ち」として端末に残り、あとから送れます。
- 端末が 48 kHz に対応していない場合、実際のレートで録音され、画面に表示されます。
- 権限は「Drive のファイルの閲覧・作成」です (`drive` スコープ)。テストユーザーの自分だけが使えます。トークンは端末のブラウザの中にだけ保存されます。
